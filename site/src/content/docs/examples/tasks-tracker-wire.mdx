This page shows what [Tasks Tracker](/examples/tasks-tracker/) sends and receives over HTTP. The generated Axum server speaks JSON:API 1.1: every request and response body is `application/vnd.api+json`. The [wire contract](https://github.com/sksizer/rust-ontogen/blob/main/docs/jsonapi-wire-contract.md) is the full specification, the [server transports guide](/guides/server-transports/) explains how the routes are generated, and [Upgrading](/reference/upgrading/) lists what changed for existing clients.

To run the server yourself:

```sh
cd examples/tasks-tracker
PORT=39102 cargo run    # without PORT it serves on 3002
```

Every pair below was captured from a real run against a scratch copy of `data/`, with `curl -sg -i` (`-g` so the brackets in `page[limit]` and `filter[status]` reach the server as written). The requests ran in the order shown, so each one sees the writes before it. Response bodies are formatted with `jq`. Of the response headers, only the status line, `Content-Type`, `Location`, `Allow` and `Vary` are shown.

Tasks Tracker pages every list (`page[offset]`, `page[limit]`, default limit 20), filters and sorts the task list through a hand-written `ListTasksQuery`, and slugs ids from the title (`IdStrategy::SlugFromField("title")`). It has no custom or event ops; see [Iron Log: the wire](/examples/iron-log-wire/) for those.

## Create a task and let the server pick the id

The request has no `id`, so the store slugs one from `title`. The response is `201` with a `Location` header, and `epic` and `tags` come back under `relationships`, each with `links` to its relationship endpoint and its related resource. The record is written to `data/vault/tasks/review-the-stack.md`.

```http title="Request"
POST /api/tasks HTTP/1.1
Accept: application/vnd.api+json
Content-Type: application/vnd.api+json

{
  "data": {
    "type": "tasks",
    "attributes": {
      "title": "Review the stack",
      "status": "open/ready",
      "created": "2026-06-08",
      "body": "## Goal\n\nReview the stacked PRs.\n"
    },
    "relationships": {
      "epic": {
        "data": {
          "type": "epics",
          "id": "markdown-backend"
        }
      },
      "tags": {
        "data": [
          {
            "type": "tags",
            "id": "codegen"
          }
        ]
      }
    }
  }
}
```

## Create a task with a client id

A client may send its own `id` instead; it must be a portable ASCII id, and a taken one is `409`. This task also names its parent, so `review-the-stack` gains it as a subtask.

```http title="Request"
POST /api/tasks HTTP/1.1
Accept: application/vnd.api+json
Content-Type: application/vnd.api+json

{
  "data": {
    "type": "tasks",
    "id": "write-the-wire-pages",
    "attributes": {
      "title": "Write the wire pages",
      "status": "open/ready",
      "created": "2026-06-07",
```

## A filtered, sorted page

```http title="Request"
GET /api/tasks?filter[status]=open/ready&sort=-created,title&page[limit]=1 HTTP/1.1
Accept: application/vnd.api+json
```

## Add to a relationship

`POST` to a relationship endpoint adds the identifiers it is not already holding and answers `204` with no body. A repeated `POST` of the same tag also answers `204` and writes nothing.

```http title="Request"
POST /api/tasks/ship-the-emitter/relationships/tags HTTP/1.1
Accept: application/vnd.api+json
Content-Type: application/vnd.api+json

{
  "data": [
    {
      "type": "tags",
      "id": "release"
    }
  ]
}
```

```http title="Response"
HTTP/1.1 204 No Content
vary: Accept
```

## Delete a task

`204`, no body. The file under `data/vault/tasks/` is removed.

```http title="Request"
DELETE /api/tasks/write-the-wire-pages HTTP/1.1
Accept: application/vnd.api+json
```

```http title="Response"
HTTP/1.1 204 No Content
vary: Accept
```

## Errors

Every error is an `errors[]` document with `status`, `code`, `title` and `detail`, plus `source` when one part of the request is to blame.

A missing task is `404`, with a `code` taken from the example's `AppError` variant (`TaskNotFound` becomes `task_not_found`):

```http title="Request"
GET /api/tasks/write-the-wire-pages HTTP/1.1
Accept: application/vnd.api+json
```

```http title="Response"
HTTP/1.1 404 Not Found
content-type: application/vnd.api+json
vary: Accept

{
  "jsonapi": {
    "version": "1.1"
  },
  "errors": [
    {
      "status": "404",
      "code": "task_not_found",
      "title": "Not Found",
      "detail": "Task not found: write-the-wire-pages"
    }
  ]
}
```

A filter member the list does not declare is `400`, and `source.parameter` names it:

```http title="Request"
GET /api/tasks?filter[colour]=red HTTP/1.1
Accept: application/vnd.api+json
```

```http title="Response"
HTTP/1.1 400 Bad Request
content-type: application/vnd.api+json
vary: Accept

{
  "jsonapi": {
    "version": "1.1"
  },
  "errors": [
    {
      "status": "400",
      "code": "invalid_query_parameter",
      "title": "Bad Request",
      "detail": "`filter[colour]` is not a query parameter of this route",
      "source": {
        "parameter": "filter[colour]"
      }
    }
  ]
}
```

A method the route does not serve is `405`, and `Allow` lists the methods it does:

```http title="Request"
PUT /api/tasks/review-the-stack HTTP/1.1
Accept: application/vnd.api+json
```

```http title="Response"
HTTP/1.1 405 Method Not Allowed
content-type: application/vnd.api+json
vary: Accept
allow: GET, HEAD, PATCH, DELETE

{
  "jsonapi": {
    "version": "1.1"
  },
  "errors": [
    {
      "status": "405",
      "code": "method_not_allowed",
      "title": "Method Not Allowed",
      "detail": "PUT is not allowed here; allowed: GET, HEAD, PATCH, DELETE"
    }
  ]
}
```
